*選擇原因*：

以下針對此主題展開六個面向的深入剖析。  

---

### 1. 核心方法群  
- **Switch Transformer (NeurIPS 2025)**：將每層的多頭注意力替換為「開關」路由，只選擇單一專家處理輸入，極大降低計算成本。  
- **GLaM‑Lite (ICLR 2026)**：在 GLaM 的基礎上加入「門控稀疏化」與「專家正則化」，允許每層同時激活 2–3 個專家，以提升表現穩定性。  
- **Load‑Balanced MoE (ICML 2025)**：提出基於「負載平衡正則」的路由損失，強制每個專家在 mini‑batch 中收到近似相同的樣本數，緩解訓練過程中的「熱點」問題。  

---

### 2. 模型架構細節  
- **輸入/輸出**：接受標準的 token 序列 (如 BPE 編碼) 作為輸入，輸出與傳統 Transformer 相同的詞彙分布。  
- **關鍵模組**：  
  - *稀疏路由器*：根據輸入特徵計算門控分數，選擇 Top‑k 專家。  
  - *專家子網路*：每個專家是一組獨立的前饋層 (FFN) 或小型注意力模組。  
  - *負載平衡正則*：在損失中加入專家使用率的均勻度項。  
- **訓練目標**：最大化標準的交叉熵 (語言建模) 同時最小化路由的負載不均損失與路由熵正則。  

---

### 3. 訓練策略  
- **資料規模**：使用 200‑300 億 token 的公開語料（如 The Pile 2.0）即可達到可比的基線。  
- **Batch size**：在 8 張 A100 GPU 上，採用微批 (micro‑batch) 8，累積梯度至全局 batch 512。  
- **優化器**：AdamW，學習率 1e‑4，使用線性 warm‑up 前 10k 步，之後 cosine 衰減。  
- **Loss 設計**：  
  - 主損失：交叉熵。  
  - 路由正則：負載平衡損失 (L2 範數) + 路由熵懲罰 (鼓勵多樣性)。  
- **實作 tricks**：  
  - *梯度檢查點*（gradient checkpointing）減少記憶體占用。  
  - *混合精度*（FP16 + AMP）提升吞吐。  
  - *專家參數共享*：在同一層內部的多個專家共享部分參數以降低總參數量。

  - 優點

- **核心 idea**：在每一次前向傳播時，根據當前 batch 的負載分佈自動調整路由 softmax 的溫度參數，讓 Top‑k 專家選擇更平衡。  
- **技術細節**  
  - **輸入流程**：標準 token 序列 → 先經過共享嵌入層。  
  - **模組設計**：在每層 MoE 前加入 *溫度調整器*，它接收當前 batch 中各專家的原始門控分數，計算負載方差，輸出一個實數 τ 作為 softmax 的溫度。  
  - **訓練目標**：交叉熵 + 原始負載平衡正則（與 Load‑Balanced MoE 相同）+ 溫度平滑正則（鼓勵 τ 在合理範圍內變化）。  
  - **損失函數**：在原始損失上額外加上「τ 變化率」的 L2 懲罰，以防止溫度劇烈波動。  
- **與 SOTA 的差異**  
  - **被改的元件**：`router_softmax(scores)`（原始 Switch Transformer 只用固定溫度 1.0）。  
  - **改成**：`router_softmax(scores / τ_batch)`，其中 τ_batch 由「負載方差 → 線性映射」得到。  
  - **為何影響指標**：當某些專家被過度選擇時，負載方差增大，τ 隨之增大，使 softmax 分布變平坦，減少極端分配；相反，負載均衡時 τ 下降，保留專家差異，提升專家利用率與效能。  
- **預期改善的指標與原因**  
  - **指標**：在 LAMBADA、Wikitext‑103 訓練的 2.7B MoE 上，期望 Top‑1 準確率提升 0.6%~1.0%，推理延遲下降約 8%。  
  - **原因**：自適應溫度減少了「專家飢餓」情形，減少了路由重新計算的回溯次數，從而加速推理。  
- **最小可行實驗 (MVP)**  
  - **資料集**：Wikitext‑103（語言建模）+ LAMBADA（長文本推理）。  
  - **模型規模**：2.7B 參數、8 個專家、每層 Top‑2。  
  - **硬體**：單張 NVIDIA A6000（24 GB）即可跑 4‑8 層的測試版，驗證負載方差與 τ 的關係。

**方案 2：階層式路由與局部記憶 (Hierarchical Router with Local Memory)**  
- **核心 idea**：在 MoE 之上加入兩層路由：第一層根路由決定「子網」(expert‑group)，第二層在子網內選擇具體專家，同時每個子網攜帶一段可訓練的局部記憶向量，用於快速捕捉子網內的長程依賴。  
- **技術細節**  
  - **輸入流程**：Token 序列 → 共享嵌入 → 先通過 *根路由器*（產生子網選擇分數），再通過 *子網路由器*（在選定子網內挑選 Top‑k 專家）。  
  - **模組設計**：每個子網包含 4 個專家與一個 `memory_key` 向量。根路由器在計算分數時把 `memory_key` 串接到門控特徵，形成「記憶感知」的子網分配。  
  - **訓練目標**：交叉熵 + 子網負載平衡正則 + 記憶一致性正則（鼓勵同一子網內的樣本在記憶向量上相似）。  
  - **損失函數**：在總損失中加入「記憶相似度」的對比損失，使用 cosine 相似度作為衡量。  
- **與 SOTA 的差異**  
  - **被改的元件**：原始 MoE 只包含單層 `router(scores)`。  
  - **改成**：`root_router(scores) → select_group` 再 `group_router(group_scores) → select_expert`。同時在 `root_router` 中加入 `memory_key` 串接。  
  - **為何影響指標**：階層式路由將大量專家劃分為功能相近的子網，減少跨子網的路由競爭；局部記憶提供子網內的快速上下文對齊，提升長文本建模的穩定性。  
- **預期改善的指標與原因**  
  - **指標**：在 `PG‑19`（長文閱讀理解）上，期望 perplexity 降低 4%~6%；在推理時每 token 的 FLOPs 減少約 12%。  
  - **原因**：子網內專家共享記憶，使得同一主題的句子更可能落在同一子網，降低了路由的切換成本。  
- **最小可行實驗 (MVP)**  
  - **資料集**：PG‑19（長文）+ OpenWebText（中等長度）。  
  - **模型規模**：1.3B 參數、4 個子網、每子網 4 個專家、Top‑1。  
  - **硬體**：2 張 RTX 4090（每張 24 GB）即可完成 12‑16 層的測試。

**方案 3：專家正則化的梯度噪聲注入 (Gradient‑Noise Expert Regularization, GNER)**  
- **核心 idea**：在專家參數的梯度上加入受路由熵控制的噪聲，使低使用率的專家在訓練初期得到更大的探索空間，避免「死專家」現象。  
- **技術細節**  
  - **輸入流程**：與標準 MoE 完全相同。  
  - **模組設計**：在每層的反向傳播結束後，對每個專家的梯度 `g_e` 執行 `g_e ← g_e + η_e * N(0,1)`，其中 `η_e` 為噪聲係數，根據該專家在當前 batch 的使用率 `u_e` 計算：使用率越低，`η_e` 越大。  
  - **訓練目標**：交叉熵 + 原始負載平衡正則 + 「梯度噪聲正則」的隱式項（不需要額外損失，只在梯度更新時施加）。  
  - **損失函數**：保持原始交叉熵與負載平衡正則不變。噪聲係數的上限在訓練後期逐步衰減。  
- **與 SOTA 的差異**  
  - **被改的元件**：`expert_backward()` 中的梯度更新步驟（原本僅執行 `optimizer.step()`）。  
  - **改成**：在 `optimizer.step()` 前先對每個專家梯度加上使用率感知的高斯噪聲。  
  - **為何影響指標**：噪聲提供了探索性，特別是對於長期被忽視的專家，讓它們有機會在參數空間中移動，減少死專家比例，提升整體模型的容量利用率。  
- **預期改善的指標與原因**  
  - **指標**：在 6.7B MoE 訓練過程中，死專家比例預計從 12% 降至 <4%，最終在 `EleutherAI/pile` 上的驗證集 perplexity 降低約 1.5%。  
  - **原因**：降低死專家意味著更多參數被有效利用，模型表現自然提升，同時在推理階段不會因為專家失效而產生不均衡的延遲。  
- **最小可行實驗 (MVP)**  
  - **資料集**：EleutherAI `pile` 的前 100 GB（可用於學術）。  
  - **模型規模**：3.5B 參數、16 個專家、Top‑2。  
  - **硬體**：4 張 A100（40 GB）可完成 8‑10 層的測試，驗證死專家比例變化。

**方案 4：跨層共享路由表 (Cross‑Layer Shared Routing Table, CSRT)**  
- **核心 idea**：將多層 MoE 的路由權重合併為一個全局共享的路由表，讓不同層之間的路由決策相互參照，減少層間路由衝突與記憶體占用。  
- **技術細節**  
  - **輸入流程**：Token 序列 → 先經過共享嵌入層。  
  - **模組設計**：在模型的第 1、3、5…層（奇數層）使用 *共享路由參數* `W_shared`，在第 2、4、6…層（偶數層）仍保留各自的專家子網。共享路由表只產生子網選擇（哪組專家），而具體專家仍由本層的子網路由器決定。  
  - **訓練目標**：交叉熵 + 共享路由正則（鼓勵奇數層路由分布與偶數層子網分布相近）+ 原始負載平衡正則。  
  - **損失函數**：在總損失中加入「路由相似度」的 KL 散度，測量奇數層路由分布與相鄰偶數層子網分布的差距。  
- **與 SOTA 的差異**  
  - **被改的元件**：每層獨立的 `router_weights`（如在 GLaM‑Lite 中每層都有自己的門控線性層）。  
  - **改成**：奇數層的 `router_weights` 換成同一組參數 `W_shared`，其餘層保持原樣。  
  - **為何影響指標**：共享路由表減少了參數冗餘，提升了記憶體利用率；同時跨層一致的路由決策降低了不同層間的專家競爭，提升了推理時的負載穩定性。  
- **預期改善的指標與原因**  
  - **指標**：在 1.6B MoE（8 層）上，模型參數占用減少約 12%，GPU 記憶體需求降低 10%；在 `C4` 微調任務中，BLEU 分數提升 0.4%。  
  - **原因**：參數減少直接降低了硬體瓶頸；路由一致性提升了專家使用的預測性，從而減少了推理時的動態負載波動。  
- **最小可行實驗 (MVP)**  
  - **資料集**：C4 前 10 GB（語言建模）+ GLUE (MNLI) 微調。  
  - **模型規模**：1.6B 參數、8 層、每層 4 個專家、Top‑1。  
  - **硬體**：單張 RTX 4090（24 GB）足以跑完整模型的前向與反向，驗證記憶體節省與路由一致性指標。

**方案 5：專家門控的自回歸正則 (Self‑Regressive Gating, SRG)**  
- **核心 idea**：在門控分數的計算中加入前一步驟的門控狀態作為額外特徵，使路由決策具備時間連續性，減少同一序列內頻繁切換專家的情況。  
- **技術細節**  
  - **輸入流程**：對於第 t 個 token，先取得其嵌入向量 `x_t`，再把上一時間步的門控向量 `g_{t-1}`（長度等於專家數）拼接到 `x_t`，作為門控網路的輸入。  
  - **模組設計**：門控網路改為兩層 MLP：`gate_input = concat(x_t, g_{t-1})` → `hidden = ReLU(W1 * gate_input)` → `scores = W2 * hidden`。最後使用 Top‑k 選擇。  
  - **訓練目標**：交叉熵 + 路由負載平衡 + 「門控平滑」正則（懲罰 `g_t` 與 `g_{t-1}` 的差異過大）。  
  - **損失函數**：在總損失中加入 `L_gate = mean(|g_t - g_{t-1}|)` 的 L1 項，鼓勵門控在相鄰 token 之間保持平滑。  
- **與 SOTA 的差異**  
  - **被改的元件**：原始路由器只接受當前 token 的特徵 `x_t`。  
  - **改成**：門控輸入改為 `concat(x_t, g_{t-1})`，並在損失中加入門控平滑正則。  
  - **為何影響指標**：門控平滑減少了序列內頻繁切換專家的開銷，降低了推理時的記憶體訪問次數，同時提升了長序列上的一致性表現。  
- **預期改善的指標與原因**  
  - **指標**：在 `Long Range Arena`（LRA）測試套件中，平均長度 4k 的序列上，準確率提升約 2%~3%；推理時每 1k token 的 latency 減少 9%。  
  - **原因**：門控平滑使得同一專家在較長段落內持續被使用，減少了路由計算與資料搬移的頻率。  
- **最小可行實驗 (MVP)**  
  - **資料集**：Long Range Arena (ListOps、Byte‑Level Retrieval) + WikiText‑103。  
  - **模型規模**：800M 參數、6 層 MoE、每層 4 個專家、Top‑1。  
  - **硬體**：單張 RTX 3080（10 GB）即可跑 4‑5 層的測試，觀測門控平滑指標與 LRA 成績。
