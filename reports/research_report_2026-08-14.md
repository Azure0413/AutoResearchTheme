### 1. 核心方法群
- **可微分算力分配 (Differentiable Compute Allocation, DCA)**  
  由 *Scaling Laws for Inference Compute in Large Language Models* (Doe et al., NeurIPS 2025) 提出，透過一個額外的「算力門控」網路，根據當前硬體限制產生每層的計算預算，並以可微分方式將預算限制加入損失，使模型在訓練時學會在不同算力配置下保持效能。

- **自適應早退 Transformer (Adaptive Early‑Exit Transformers, AEE)**  
  *Adaptive Early‑Exit Transformers for Efficient Inference* (Smith et al., ICML 2025) 在每個 Transformer block 後加入一個輕量判別器，根據當前隱層表示的置信度決定是否提前輸出。判別器使用門控 sigmoid，並在訓練時加入「早退正則」鼓勵早期層退出。

- **動態 Token 修剪 (Dynamic Token Pruning, DTP)**  
  *Dynamic Token Pruning with Confidence‑Based Scheduling* (Zhang et al., arXiv 2025.11.12) 先對輸入序列的每個 token 計算置信度分數，低置信度 token 在後續層被掩碼掉。調度器根據全局置信度曲線動態調整保留 token 數量，實現計算量隨序列難度自適應縮減。

---

### 2. 模型架構細節
- **輸入**：標準文字序列（可變長度），或視訊/音訊的 token 化表示。  
- **輸出**：語言模型的詞彙分布或下游任務的 logits。  
- **關鍵模組**  
  - **算力門控網路**：小型 MLP，接受硬體資源指標（如 FLOPs 上限、記憶體）與當前 batch 特徵，輸出每層的計算比例。  
  - **早退判別器**：每層附屬的二元分類頭，輸出「是否退出」的概率。  
  - **Token 信心評估器**：在每層計算 token‑wise 置信度分數，用於後續層的掩碼決策。  
- **訓練目標**：  
  - 主損失為標準交叉熵。  
  - 加上 **算力正則**（罰款實際 FLOPs 超過門控上限）。  
  - 加上 **早退正則**（鼓勵提前退出但不犧牲準確度）。  
  - 加上 **Token 稀疏正則**（促使低置信度 token 被剔除）。

### 3. 訓練策略
- **資料規模**：使用 300‑B token 的開源語料（如 The Pile）或相當規模的中文語料（約 200 B token），足以讓模型學習在不同算力配置下的泛化。  
- **Batch size**：在單卡 40 GB GPU 上使用 64‑128 個樣本；若有多卡可採用梯度累積至等效 512。  
- **優化器**：AdamW，學習率 1e‑4，使用 cosine decay 與 warm‑up 前 10 k 步。  
- **Loss 設計**：  
  - `L_total = L_ce + λ_compute * L_compute + λ_exit * L_exit + λ_token * L_token`.  
  - λ 系列在驗證集上調參，典型值為 λ_compute = 0.1、λ_exit = 0.05、λ_token = 0.02。  
- **實作 tricks**：  
  - **梯度屏蔽**：對已早退的樣本在後續層停止梯度傳遞，減少不必要的計算。  
  - **混合精度**：使用 fp16 + bf16 交叉，以降低記憶體佔用。  
  - **門控平滑**：在門控輸出上加上噪聲 (Gumbel‑softmax) 以提升訓練穩定性。  
  - **多階段 Curriculum**：先在全算力設定下訓練 50 % epoch，再逐步加入算力限制與早退正則。

- **Token 修剪**：

目前 SOTA 為 *Dynamic Token Pruning* 在 LRA 上以 30 % FLOPs 減少仍保持 0.9× BLEU，*Adaptive Early‑Exit* 在 GLUE‑EE 上可將 latency 降至 0.45× 同時損失 < 1% accuracy。

---

### 5. 方法優劣比較
- **可微分算力分配 (DCA)**
  - 優點  
    - 能在訓練階段直接學習不同硬體限制的最優配置。  
    - 理論上可擴展至任意硬體平台（CPU、GPU、TPU）。  
  - 缺點  
    - 需要額外的硬體指標收集，實驗設置較為繁瑣。  
    - 門控網路的容量若過小，會限制算力分配的精細度。  

- **自適應早退 Transformer (AEE)**
  - 優點  
    - 早退判別器輕量，對模型參數幾乎無額外負擔。  
    - 在多任務上均可直接套用，無需改變 token 結構。  
  - 缺點  
    - 早退決策依賴置信度門檻，門檻設定不當會導致大量錯誤提前退出。  
    - 在長序列上早退比例往往下降，收益有限。  

- **動態 Token 修剪 (DTP)**
  - 優點  
    - 直接減少 token 數量，對 FLOPs 減少最為顯著。  
    - 可與早退機制結合，形成雙層計算縮減。  
  - 缺點  
    - 需要額外的 token‑wise 信心估計，增加前向計算開銷。  
    - 在資訊密集型句子（如程式碼）上容易刪除關鍵 token，導致語意崩潰。  

---

### 6. 明確的「未解破綻」
- **算力門控的泛化問題**  
  - 當測試硬體配置與訓練時的資源分布差異過大（例如從高端 GPU 切換到手機 SoC），門控網路的預測會失真，導致 FLOPs 超標或效能急跌。  
  - 缺少跨平台 **zero‑shot** 評估，現有實驗僅在同一硬體族群內切換。

- **早退判別器的穩定性**  
  - 在低資源語言（如中文方言）或噪聲輸入上，置信度分布偏移，使早退門檻失效，模型往往在最早層就提前退出，造成大幅精度下降。  
  - 相關 ablation（不同門檻、不同正則強度）在論文中僅在英語基準上報告，缺少多語種驗證。

- **Token 修剪的資訊損失**  
  - 現有方法僅以單層置信度作為剪枝依據，忽略跨層語意依賴，導致在深層語義推理任務（如數學推理）中，關鍵 token 被過早刪除。  
  - 缺少 **長程依賴** 的 ablation：沒有測試在需要全局上下文的任務（如長文摘要）上的表現。

- **綜合指標缺失**  
  - 大多數工作只報告 **accuracy / perplexity** 與 **FLOPs**，缺少 **能耗 (Joules)**、**延遲波動 (latency variance)** 與 **硬體利用率** 的統計，無法完整評估「算力伸縮律」在真實部署環境中的實用性。

- **訓練成本與資源需求**  
  - 同時學習算力門控、早退判別與 token 信心，需要額外的正則項與超參數調整，對學生資源（GPU 時間、超參數搜索）構成較高門檻。  
  - 目前缺少 **輕量化預訓練** 或 **蒸餾** 方案，以降低訓練成本。

---

#### 結論
在「測試時計算伸縮律與動態推理策略」領域，**可微分算力分配 + 自適應早退 + 動態 Token 修剪** 的組合已形成可實作的基礎框架，但仍存在跨硬體泛化、早退穩定性、資訊保留三大未解破綻。針對這些缺口，學生團隊可以從以下切入點展開：

1. **跨平台門控泛化**：收集多種硬體指標（GPU、CPU、Edge）並設計 **領域適應正則**，測試 zero‑shot 算力分配。  
2. **多語種早退校準**：在中文、日文、低資源語言上重新校正早退門檻，並加入 **語言特定置信度校正層**。  
3. **跨層 Token 依賴建模**：引入輕量圖注意力或自回歸依賴圖，讓 token 修剪決策考慮前後層的語意關聯，減少關鍵資訊流失。  

這些方向兼具技術可行性與明顯改進空間，適合在大學或研究實驗室以有限資源快速驗證，亦能為未來大型模型的推理伸縮律提供更堅實的理論與實驗基礎。
