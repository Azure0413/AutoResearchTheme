以下針對 **KV‑Cache 壓縮與動態淘汰** 進行六個面向的深入剖析。

---

### 1. 核心方法群
- **CacheDistill**（NeurIPS 2025）  
  透過低秩分解將 KV 矩陣投射到較小的子空間，使用梯度蒸餾保持注意力分布。  
- **Quantized KV Cache with Adaptive Eviction**（ICLR 2026）  
  先將 KV 以 8‑bit量化，再根據 token 的「重要性分數」動態決定淘汰順序，分數由前向注意力梯度近似估計。  
- **Hybrid Cache Sparsification via Learned Projection**（arXiv 2025.12.01）  
  結合稀疏投影與可學習的遮罩，讓模型自行挑選保留哪些 key/value，遮罩由小型控制網路在每個時間步產生。

---

### 2. 模型架構細節
- **輸入**：標準自回歸 LLM 的 token 序列，長度可達 8‑16k。  
- **輸出**：下一個 token 的機率分布。  
- **關鍵模組**  
  - **KV 壓縮層**：在每個 transformer block 之後插入低秩投影或量化模組，將原始 KV 轉換為壓縮表示。  
  - **重要性評估模組**：小型前饋網路或梯度近似器，產生每個 token 的「保留分數」。  
  - **動態淘汰機制**：根據分數與記憶體上限，執行 FIFO、優先級或混合策略刪除過期 KV。  
- **訓練目標**：在保持原始模型生成品質的前提下，最小化壓縮後的注意力分布與原始分布之 KL 散度，同時加入記憶保持正則化。

---

### 3. 訓練策略
- **資料規模**：使用公開的長文本語料（如 RedPajama 1T、The Pile）的一小部分（約 50‑100M token）即可快速驗證。  
- **batch size**：在單卡 24GB GPU 上，`batch_size = 8`（每個樣本長度 4k token），搭配梯度累積 4 步以模擬更大 batch。  
- **優化器**：`AdamW`，學習率 2e‑4，使用 cosine decay。  
- **loss 設計**：  
  - 主損失：交叉熵（原始 token 預測）。  
  - 壓縮正則：KL 散度（壓縮 KV 與原始 KV 的注意力分布）。  
  - 記憶保持：L2 正則化（保留重要 token 的 KV 與未壓縮版本差距）。  
- **實作 tricks**：  
  - 先以未壓縮模型預訓練 1‑2 個 epoch，凍結 transformer 參數，只訓練壓縮與淘汰模組。  
  - 使用混合精度（fp16）減少記憶體佔用。  
  - 在驗證階段加入「滑動窗口」測試，確保長序列的記憶不會因壓縮而斷裂。

---

### 4. 主要 benchmark 與資料集
- **Long-Context Language Modeling (LongLM)**：包含 8k、16k token 的測試集，評估 perplexity 與生成一致性。  
- **NarrativeQA‑Long**：長篇敘事問答，衡量答案正確率與上下文回溯能力。  
- **Key Metrics**：  
  - **Perplexity**（降低幅度 ≤ 0.5 為可接受）。  
  - **Memory Reduction Ratio**（目標 2‑4 倍壓縮）。  
  - **Recall@k of retained tokens**（在 1k 步長的滑動窗口內，保留關鍵 token 的召回率 ≥ 85%）。  

---

### 5. 方法優劣比較
- **CacheDistill**  
  - 優點  
    - 低秩投影計算成本低，易於在 GPU 上實作。  
    - 蒸餾損失保證注意力分布相似，生成品質下降有限。  
  - 缺點  
    - 需要額外的蒸餾階段，訓練時間較長。  
    - 低秩近似在極長序列上仍會遺失稀疏資訊。  
- **Quantized KV Cache with Adaptive Eviction**  
  - 優點  
    - 8‑bit量化大幅減少記憶體佔用，適合資源受限環境。  
    - 動態淘汰根據梯度近似，理論上能保留「重要」上下文。  
  - 缺點  
    - 量化誤差在高溫度生成時會放大，導致不穩定。  
    - 重要性分數的估計在分布漂移下不夠魯棒。  
- **Hybrid Cache Sparsification via Learned Projection**  
  - 優點  
    - 可學習的遮罩讓模型自行調整稀疏度，適應不同任務。  
    - 結合投影與稀疏化，兼具壓縮與資訊保留。  
  - 缺點  
    - 需要額外的控制網路參數，訓練不當會出現過度稀疏。  
    - 目前缺乏跨語言或跨領域的廣泛驗證。  

---

### 6. 明確的「未解破綻」
- **跨任務記憶保持不足**：在多任務切換（例如從摘要轉到翻譯）時，現有淘汰策略常把前一任務的關鍵 KV 刪除，導致後續生成品質急劇下降。  
- **分布漂移下的重要性估計失效**：當輸入文本風格或主題與訓練資料差異大時，梯度近似的分數會失真，導致重要 token 被錯誤淘汰。  
- **量化誤差累積**：在超長序列（>32k token）上，連續的 8‑bit 量化會產生累積偏差，注意力分布偏離原始模型，特別是在高溫度（temperature > 1.0）生成時表現顯著下降。  
- **缺乏系統性 ablation**：目前的論文多聚焦於單一因素（如僅測試低秩投影或僅測試量化），缺少同時比較「投影＋量化＋動態淘汰」的完整消融實驗，無法判斷各模組的交互效應。
