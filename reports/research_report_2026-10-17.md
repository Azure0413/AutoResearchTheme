### 1. 核心方法群

    2. **不確定性加權**：將 `σ` 取倒數作為權重 `w = 1/σ`，與原始 logits 相乘後再做 softmax，得到加權後的 `p_subtree`。  
    3. **下層門控**：在被選中的子樹內，仍使用標準 top‑k gating。  
  - **訓練目標**：主語言建模交叉熵 + 路由平衡正則 + **不確定度正則**（鼓勵高置信度 token 走較少的子樹）。  
  - **損失函數**：  
    - 主損失：語言模型交叉熵。  
    - 平衡正則：子樹選擇頻率接近均勻。  
    - 不確定度正則：對於高置信度 token（低 `σ`），加大其子樹選擇的熵懲罰，使其更專注於少數子樹。  
- **與 SOTA 的差異**  
  - **改動位置**：在 *Hierarchical MoE*（ICLR 2026）Algorithm 2 第 7 行，原本的 `logits = MLP_up(x)` 改為 `logits = (MLP_up(x) ⊙ (1/σ))`，即加入不確定度倒數作為 element‑wise 加權。  
  - **影響**：上層門控不再僅依賴 token 本身的特徵，而是同時考慮模型對該 token 的信心，從而在高置信度情況下更集中於少數子樹，提升專家利用率，降低路由漂移。  
- **預期改善的指標與原因**  
  - **指標**：在 *The Pile* 200B 文字預訓練上，預期 **專家利用率提升 12 %**，同時 **困惑度下降 0.04**。  
  - **原因**：不確定度加權讓路由更具區分性，減少無效切換，提升前向傳播的訊息一致性。  
- **最小可行實驗 (MVP)**  
  - **資料集**：OpenWebText（約 40 GB）。  
  - **模型規模**：2‑層 HM‑MoE，每層 8 個子樹、每子樹 4 個專家，隱藏維度 512。  
  - **硬體需求**：單張 RTX 4090 可完成 8‑GPU 等效的微批次訓練（使用梯度累積）。  
  - **驗證指標**：比較 baseline HM‑MoE 的專家利用率與本方法的提升幅度。

**方案 2：動態子樹重組與負載平衡 (Dynamic Subtree Rewiring for Load Balancing, DSR‑LB)**  
- **核心 idea**：在訓練過程中定期根據子樹的實際利用率重新排列樹結構，將長期閒置的專家搬移至利用率較高的子樹，保持路由負載均衡。  
- **技術細節**  
  - **輸入流程**：與 *Tree‑Structured MoE*（NeurIPS 2025）相同，token → 位置編碼 → 逐層門控。  
  - **模組設計**：  
    1. **利用率統計緩衝**：每 1 k 步收集每個子樹的 top‑k 被選次數。  
    2. **子樹重組演算法**：在第 `t` 步（每 5 k 步觸發），執行以下流程：  
       - 計算子樹利用率向量 `u`.  
       - 若 `u_i` 低於全體平均的 30 % ，則挑選該子樹內最閒置的專家 `e_low`。  
       - 從利用率最高的子樹 `j` 中挑選一個負載較重的專家 `e_high`，交換兩者的參數（權重、偏置）並更新門控的子樹映射表。  
    3. **門控更新**：交換後立即刷新上層門控的子樹索引參數，使其在下一步使用新結構。  
  - **訓練目標**：與原始 *Tree‑MoE* 相同的語言模型交叉熵 + 路由平衡正則。  
  - **損失函數**：不另加額外項，重組本身是無梯度操作。  
- **與 SOTA 的差異**  
  - **改動位置**：在 *Tree‑MoE* 訓練循環的第 12 行（原本僅做 forward/backward），插入 **`if step % 5000 == 0: RewireSubtrees()`**，其中 `RewireSubtrees` 為上述重組演算法。  
  - **影響**：動態調整子樹結構直接解決「部分子樹長期閒置」的問題，提升整體專家利用率，並減少因路由偏移產生的梯度噪聲。  
- **預期改善的指標與原因**  
  - **指標**：在 *C4* 100B 訓練語料上，**專家利用率提升 15 %**，同時 **訓練收斂速度提升約 8 %**（相同步數下困惑度下降更快）。  
  - **原因**：重組保證每個子樹都有足夠的活躍專家，避免梯度只聚焦於少數參數，提升參數更新的有效性。  
- **最小可行實驗 (MVP)**  
  - **資料集**：WikiText‑103。  
  - **模型規模**：3 層 Tree‑MoE，每層二叉樹深度 2（共 4 個子樹），每子樹 2 個專家，隱藏維度 256。  
  - **硬體需求**：單張 RTX 3080 足以完成 2 天訓練，使用梯度累積。  
  - **驗證指標**：比較重組前後的子樹利用率分佈與驗證集困惑度。

**方案 3：稀疏專家自適應深度 (Adaptive Expert Depth, AED)**  
- **核心 idea**：讓 token 在階層 MoE 中根據自身置信度決定是否繼續向下層專家進行計算，實現「早退」機制，減少不必要的計算並提升推理效率。  
- **技術細節**  
  - **輸入流程**：token → 位置編碼 → 上層門控。  
  - **模組設計**：  
    1. **上層門控**：輸出子樹概率 `p_subtree` 與置信度分數 `c`（由門控最後的 sigmoid 輸出）。  
    2. **早退判定**：若 `c` 大於預設門檻 `τ`（如 0.85），則直接將 token 的表示傳遞至後續 Transformer 層，跳過下層專家計算。  
    3. **下層門控**：僅對未早退的 token 進行細粒度專家選擇。  
  - **訓練目標**：主語言模型交叉熵 + **早退正則**（鼓勵高置信度 token 早退，懲罰過多層次計算的 token）。  
  - **損失函數**：  
    - 主損失：語言模型交叉熵。  
    - 早退正則：對每個 token 加上 `λ * (1 - c)`，其中 `λ` 為超參數，促使模型在容易預測的情況下降低置信度門檻。  
- **與 SOTA 的差異**  
  - **改動位置**：在 *Deep Hierarchical Gating*（arXiv 2025.12）Algorithm 3 第 9 行，原本的 `output = ExpertForward(x, selected_expert)` 改為  
    ```
    if confidence > τ:
        output = x   // 直接跳過
    else:
        output = ExpertForward(x, selected_expert)
    ```  
  - **影響**：通過置信度門檻控制計算深度，減少低信息量 token 的多層專家運算，提升推理速度，同時保留對難例的深層處理，避免精度下降。  
- **預期改善的指標與原因**  
  - **指標**：在 *EleutherAI Pile* 小規模測試（30B tokens）上，**平均推理 FLOPs 減少約 22 %**，而 **驗證集困惑度僅上升 0.01**。  
  - **原因**：早退機制讓大部分簡單 token 只經過上層門控，減少冗餘計算，同時保留難例的全深度路由，保持模型表現。  
- **最小可行實驗 (MVP)**  
  - **資料集**：OpenWebText。  
  - **模型規模**：2 層 HM‑MoE，隱藏維度 384，子樹 4 個，每子樹 2 個專家。  
  - **硬體需求**：單張 RTX 4090 可在 12 小時內完成 10M 步訓練。  
  - **驗證指標**：測量 FLOPs、推理延遲與驗證困惑度的變化。

**方案 4：雙向路由正則化 (Bidirectional Routing Regularization, BRR)**  
- **核心 idea**：在階層 MoE 中加入一個逆向門控，使下層的專家選擇能被上層門控「重建」，藉此強化路由一致性，降低子樹之間的訊號漂移。  
- **技術細節**  
  - **輸入流程**：token → 位置編碼 → 上層門控 → 下層門控 → 專家。  
  - **模組設計**：  
    1. **正向門控**：與 *HM‑MoE* 相同，產生子樹分布 `p_subtree`，再在子樹內產生專家分布 `p_expert`.  
    2. **逆向門控**：在同一 forward pass 中，從下層選出的專家索引 `e_idx` 逆向映射回子樹概率 `\hat p_subtree`（使用小型 MLP 讀取專家嵌入）。  
    3. **雙向一致性損失**：計算 `p_subtree` 與 `\hat p_subtree` 的 KL 散度，加入總損失。  
  - **訓練目標**：語言模型交叉熵 + 路由平衡正則 + **雙向一致性正則**。  
  - **損失函數**：  
    - 主損失：語言模型交叉熵。  
    - 平衡正則：子樹與專家選擇的均衡。  
    - 雙向正則：`KL(p_subtree || \hat p_subtree)`，鼓勵正向與逆向路由保持一致。  
- **與 SOTA 的差異**  
  - **改動位置**：在 *Hierarchical MoE*（ICLR 2026）forward 函數的第 15 行，原本僅返回 `output = ExpertForward(x, e_idx)`，改為  
    ```
    output = ExpertForward(x, e_idx)
    hat_p_subtree = InverseGate(e_idx, expert_embedding)
    consistency_loss = KL(p_subtree, hat_p_subtree)
    ```  
    並在總損失中加入 `consistency_loss`。  
  - **影響**：逆向門控迫使上層門控在選擇子樹時考慮下層專家的可恢復性，減少子樹之間的「孤島」現象，提升路由的全局一致性與穩定性。  
- **預期改善的指標與原因**  
  - **指標**：在 *C4* 50B 訓練上，**路由偏移率下降約 30 %**（即子樹切換頻率減少），同時 **驗證集困惑度下降 0.03**。  
  - **原因**：雙向正則強化了門控的協同學習，使得路由決策更具可解釋性與穩定性，減少因隨機噪聲導致的專家閒置。  
- **最小可行實驗 (MVP)**  
  - **資料集**：WikiText‑103。  
  - **模型規模**：1 層 HM‑MoE，子樹 3 個，每子樹 3 個專家，隱藏維度 256。  
  - **硬體需求**：單張 RTX 3080 可在 6 小時內完成 5M 步訓練。  
  - **驗證指標**：比較路由偏移率（子樹切換次數）與 baseline 的差異，同時報告驗證困惑度。

**## 2. 核心研究方法**  
我們提出 **Hierarchical Uncertainty‑Guided Routing with Dynamic Subtree Rebalancing (HUGR‑DSR)**，結合三大要素：  
1. **階層式路由**：兩層門控，上層負責粗粒度子樹選擇，下層在子樹內執行 top‑k 專家挑選。  
2. **不確定性加權**：利用變分推理得到每個 token 的不確定度 `sigma`，以 `1/sigma` 加權上層門控 logits，使高置信度 token 集中於少數子樹，降低路由噪聲。  
3. **動態子樹重組**：每 5 k 步統計子樹利用率 `u`，將低於平均 30 % 的子樹與高負載子樹交換，保持長期負載均衡且不需額外梯度。

**演算法步驟**  
- **Step 1**：對輸入 token 計算基礎表示 `h`（Transformer 前置層）。  
- **Step 2**：變分網路 `q_phi(sigma|h)` 輸出不確定度 `sigma`，同時計算上層門控 logits `g1 = MLP1(h)`.  
- **Step 3**：將 `g1` 乘以權重 `w = 1 / sigma`，得到加權 logits `g1' = g1 ⊙ w`，再經 softmax 取前 `K1` 個子樹。  
- **Step 4**：在每個被選子樹內，使用傳統 top‑k gating `g2 = MLP2(h)` 挑選 `K2` 個專家，執行前向。  
- **Step 5**：計算總損失 `L = L_lm + λ1 * L_balance + λ2 * L_uncertainty`，其中 `L_uncertainty` 為 KL 散度正則，鼓勵 `sigma` 不致過度收縮。  
- **Step 6**：每 `T = 5k` 步執行 `RewireSubtrees()`：根據子樹利用率 `u` 重新映射子樹索引，更新上層門控參數的子樹嵌入向量。  

**訓練目標**  
- 最小化語言模型交叉熵。  
- 同時平衡專家利用率（`L_balance`）與不確定度正則（`L_uncertainty`）。  

**推論流程**  
- 只保留 **上層加權 logits** 與 **下層 top‑k**，不再計算 `sigma`（可用訓練時的 EMA 近似），大幅減少推理開銷。
