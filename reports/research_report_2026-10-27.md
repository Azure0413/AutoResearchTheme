### 1. 核心方法群
- **Ensemble‑Driven Speculative Decoding (ESD)**  
  以多個小型草稿模型同時產生候選 token 序列，主模型僅在「不確定」區段重新計算注意力，透過投票機制決定最終輸出。  
- **Dynamic Confidence‑Weighted Draft Fusion (DCDF)**  
  為每個草稿模型預測一個置信度分數，根據置信度動態調整草稿的採樣比例，低置信度的草稿會被主模型提前校正。  
- **Cross‑Model Speculative Decoding (CMSD)**  
  結合跨語言/跨領域的草稿模型（例如代碼模型 + 文本模型），在同一時間步產生多樣化的草稿，主模型使用「跨模型相似度」作為篩選依據，提升低延遲下的生成品質。

---

### 2. 模型架構細節
- **輸入**：  
  - 前置上下文 `C`（可長至 8k token）  
  - 多個草稿模型的輸出序列 `D_i`（i 為草稿模型索引）  
- **輸出**：  
  - 主模型最終生成的 token 序列 `Y`  
- **關鍵模組**：  
  - **草稿產生器**：輕量化 Transformer 或 LoRA‑微調版 LLM，負責快速產生候選 token。  
  - **置信度估計器**：小型前饋網路，接受草稿的隱狀態輸出置信度分數。  
  - **投票/融合模組**：基於置信度或相似度的加權投票機制，決定哪些 token 直接接受、哪些需交由主模型重新計算。  
  - **主模型校正器**：完整的大型 LLM，僅在「被挑選」的 token 上執行注意力運算，其他 token 直接繼承草稿結果。  
- **訓練目標**：  
  - 草稿模型：最小化與主模型產出的交叉熵，保持語意一致。  
  - 置信度估計器：二元交叉熵，標籤為「主模型是否需要重新計算」的真實情況。  
  - 融合模組：整體序列的負對數似然（NLL），鼓勵高置信度草稿被直接接受。

### 3. 訓練策略
- **資料規模**：使用開源指令追蹤資料集（如 `OpenWebText`、`The Pile`）的子集，約 200 M 句子，足以讓草稿模型學會基本語言結構。

**## 1. 研究痛點與背景**  
- 現代大語言模型在長上下文推論時，KV 快取記憶體佔用與注意力計算成本呈指數增長，導致 8k‑token 以上的應用在單張 24‑48 GB GPU 上難以實時運行。

**因此**，需要同時解決 KV 快取壓縮的匹配精度與投機解碼的計算浪費兩大瓶頸，才能在單卡 GPU 上實現 8k‑token 以上的低延遲生成。

**## 2. 核心研究方法**  
本提案結合 **階層式位寬自適應 KV 快取 (HBKVC)** 與 **置信度導向草稿分段投機解碼 (CGSSD)**，形成一個「**分段‑層次‑自適應**」的推論框架。概念上，先以 HBKVC 以兩層量化壓縮 KV，保持粗粒度相似度；再以 CGSSD 在置信度低的局部段落觸發主模型重新計算，避免全局回算。

**演算法步驟**  
1. **KV 初始化**：對每個注意力層的快取向量先做 8‑bit 粗量化，產生 `coarse_code`；同時根據局部方差自適應選擇是否啟用 2‑bit 細量化，產生 `fine_code`。  
2. **草稿生成**：使用兩個輕量草稿模型（`draft_A`、`draft_B`）同時產生候選 token 序列 `D_i`，並輸出每個 token 的置信度分數 `conf_i`。  
3. **置信度分段門控**：以滑動窗口（長度 16）計算窗口內平均置信度；若低於門檻 0.6，標記該窗口為 **需重算段**。  
4. **分段投機解碼**：對於「需重算段」直接呼叫完整 LLM（`main_model`）重新計算注意力與 KV；對於其他段落直接使用 HBKVC 壓縮後的 KV 進行快速查詢。  
5. **融合與輸出**：將草稿模型的 token 與主模型重算的 token 依據置信度加權投票，生成最終輸出序列 `Y`。  

**訓練目標**  
- `L_ce`：草稿模型與主模型的交叉熵損失。  
- `L_conf`：置信度預測的二元交叉熵。  
- `L_recon`：HBKVC 粗/細量化的重建誤差。  
- `L_total = L_ce + λ1·L_conf + λ2·L_recon`（`λ1≈0.3`、`λ2≈0.2`）。  

**推論流程**  
- 輸入長上下文 `C` → HBKVC 壓縮 KV → 同時執行草稿模型與置信度門控 → 只在低置信度段落喚醒 `main_model` → 融合產出 `Y`。
